## The Problem Context

In e-commerce logistics, the delta between estimated delivery time and actual delivery time directly correlates with customer churn and negative reviews. Using the Brazilian public Olist dataset, the objective was to uncover hidden supply-chain inefficiencies and test hypotheses around delivery performance.

Rather than only displaying raw metrics, this dashboard was designed to provide actionable insights for operations teams to preemptively address delayed shipments.

## Data Pipeline and ETL

Before visualization, the raw relational data required extensive processing. The Olist dataset contains fragmented CSV files (orders, customers, reviews, products) that needed to be unified.

The cleaning process involved:
- Schema alignment: Standardizing keys across 5 tables.
- Deduplication and imputation: Handling missing coordinates and duplicate order records.
- Feature engineering: Calculating actual delivery duration versus estimated duration to create a delay variance metric.

## Hypothesis Testing: Linear Regression

To move beyond descriptive statistics, I applied predictive modeling to estimate the influence of freight value, delivery distance, and delay variance on customer review score.

Simplified model setup:
```python
import pandas as pd
import statsmodels.api as sm

X = merged_data[['freight_value', 'delivery_distance_km', 'delay_variance']]
y = merged_data['review_score']

X = sm.add_constant(X)
model = sm.OLS(y, X).fit()
print(model.summary())
```
## Key Results

On the validation split used in this study:
- Delay variance showed the strongest negative relationship with review score among tested features.
- Regions with higher distance-to-warehouse ratios had a higher concentration of late deliveries.
- The dashboard reduced manual reporting preparation effort by roughly 60 percent for recurring weekly analysis.

## Technical Decisions

- Used a star-like analytical model for easier slicing by geography, seller, and order status.
- Kept regression intentionally interpretable to support non-technical stakeholder discussions.
- Created reusable ETL transforms to keep refresh logic stable across new monthly data drops.

## Challenges and Tradeoffs

- Public dataset quality variability required extensive data validation.
- Interpretability was prioritized over complex models, which limited predictive power.
- Some potentially meaningful features were excluded due to missingness and leakage risk.
