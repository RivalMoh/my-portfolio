## The Problem Context

Indonesia has a disaster vulnerability score of 43.5%. During crises, information spreads through chaotic WhatsApp chains, leading to misinformation and delayed responses. Worse, victims in a state of panic, with injuries, or facing severe weather, cannot easily complete detailed forms.

**The Solution:** A "Zero-Friction" reporting tool. Hold one button, speak naturally, let the AI do the rest.

### Value Proposition

| Audience                     | Benefit                                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| **General Public**           | No app download required (PWA). Works on any browser. Minimal digital literacy needed.                |
| **Authorities (BPBD / SAR)** | Raw panic audio → structured JSON (location, hazard type, severity, coordinates) on a live dashboard. |

## System Architecture

The system uses a decoupled frontend-backend architecture, leveraging Google's Gemini 2.5 Flash Lite to bypass traditional Speech-to-Text pipelines.

```text
┌─────────────────────────────────────────────────────┐
│                    FRONTEND (PWA)                   │
│   HTML5 + Vanilla JS + Leaflet.js                   │
│   MediaRecorder API  │  Geolocation API             │
└───────────────────┬─────────────────────────────────┘
                    │  POST /report  (audio + GPS)
                    ▼
┌─────────────────────────────────────────────────────┐
│                 BACKEND (FastAPI)                   │
│                                                     │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐  │
│  │ audio_service│  │  ai_service  │  │geo_service│  │
│  │  (validate + │  │   (Gemini    │  │ (Nominatim│  │
│  │ noise reduce)│  │  multimodal) │  │  geocode) │  │
│  └──────────────┘  └──────────────┘  └───────────┘  │
│                                                     │
│                 SQLite Database                     │
└─────────────────────────────────────────────────────┘
```

* **Frontend:** Runs entirely in the browser with PWA system no need of app install. Captures audio via `MediaRecorder`, obtains GPS via the `Geolocation API`, and renders reports on an interactive `Leaflet.js` map.
* **Backend:** Python + FastAPI (async). Handles file validation, audio processing, AI analysis, geocoding, and persistence.
* **AI Engine:** Google Gemini 2.5 Flash Lite (multimodal). Processes raw audio directly, producing transcription and structured extraction outputs in a single inference step.

## Processing Pipeline

To prevent hallucinated data and ensure high-quality inputs, the audio payload must pass through a strict validation and geocoding pipeline before it is stored.

```text
Audio File + GPS (optional)
        │
        ▼
1. Input Validation
   ├─ Allowed extensions: .webm .wav .mp3 .m4a .ogg
   ├─ Max file size:       10 MB
   └─ Content-Type check
        │
        ▼
2. Audio Quality Validation  (librosa)
   ├─ Min duration:    2 seconds
   ├─ Min RMS energy:  0.01
   └─ Non-silent frames > 10%
        │
        ▼
3. Noise Reduction  (noisereduce + soundfile)
   └─ Outputs a clean .wav file
        │
        ▼
4. Reverse Geocoding  (geopy / Nominatim)  ← only if GPS provided
   └─ lat/lon → human-readable address (location_context for estimated)
        │
        ▼
5. AI Analysis  (Gemini 2.5 Flash Lite)
   └─ Returns JSON: {transcription, hazard, severity, location...}
        │
        ▼
6. Forward Geocoding  (geopy / Nominatim)
   └─ AI-extracted location name → lat/lon coordinates
        │
        ▼
7. Persist to Database  (SQLite)
```

## Key Innovations

1. **Multimodal Extraction (Speech-to-Text Pipeline):** Users can upload audio directly to Gemini. The system performs both transcription and structured data extraction the output will including hazard type, severity, location, and description in a single model inference. This approach eliminates the reliance on fragile Speech-to-Text (STT) pipelines and significantly reduces latency.
2. **Context-Grounded AI:** The system reverse-geocodes GPS coordinates and incorporates them into the Gemini prompt as location context. This prevents misunderstandings when the speaker is vague (e.g., using phrases like "di sini" or "right here") by grounding the AI's comprehension in the user's actual physical location.
3. **Audio Quality Gate:** Before calling the AI, which utilizes API resources, the backend validates every recording using the Librosa library. It rejects recordings that are blank, contain only noise, or are accidental presses, thereby conserving API calls.
4. **Disaster Classification Filter:** The AI returns a classification of `is_disaster: true/false` along with a validation code (OK | NO_SPEECH | NOT_DISASTER | UNCLEAR). Non-disaster submissions are filtered out before being stored in the database.

## Technical Limitations & Mitigations

1. **Network Dependency**
	* **Bottleneck:** The app sends approximately 500 KB audio payloads to the Gemini API. In situations of total network blackout or in zones with only 2G connectivity, audio uploads may time out.
	* **Mitigation:** Future versions of the app should implement a fallback to a lightweight text-only HTML form in cases where audio uploads time out, ensuring graceful degradation.
2. **Audio Quality Ceiling**
	* **Bottleneck:** Heavy rain can overwhelm a cheap smartphone microphone, making it difficult to capture a human voice clearly. The noisereduce algorithm cannot recover signals that were never properly captured.
	* **Mitigation:** Introduce a visual confirmation step, allowing users to upload a photo for secondary evidence when audio quality is insufficient.
